Amazon FBA Profit Calculator: What the Estimate Includes—and What It Doesn't

Before sourcing a product, learn which Amazon FBA and MFN fees a profit estimate models, which inputs can distort it, and which seller costs still belong in your own margin calculation.

November 25, 2026 8 min read Pangol Info Team

Can an Amazon FBA calculator tell you whether a product will be profitable before you buy inventory? It can help compare Amazon’s fulfillment-fee scenarios, but the word “profit” needs a boundary. The Revenue Calculator API returns an Amazon-fee estimate for an ASIN and marketplace; it does not replace your own landed-cost and operating-cost model.

Compare fulfillment paths on the same assumptions

The Amazon Revenue Calculator API takes a product ASIN and a marketplace country. Its documented supported countries are US and JP. It can return fee summaries for both Fulfilled by Amazon (FBA) and Merchant Fulfilled (MFN), or only the program you request. That makes it useful for an early “does this price still work under either fulfillment path?” screen.

For a fair comparison, use the same realistic selling-price assumptions for both modes. You can supply separate fbaPrice and mfnPrice, plus mfnShippingPrice for buyer-paid MFN shipping. The API can use the product’s current price when a price is omitted, but a live listing price is not necessarily your planned offer price. If you are sourcing around a target sale price, pass that price explicitly rather than letting a default silently decide the scenario.

Read the fee model before trusting its profit field

For FBA, the response separates the fulfillment fee, net referral fee, any returned fixed closing fee, and monthly storage estimates for peak and off-peak periods. Its totalCost is fulfillment plus net referral plus fixed closing fee; storage is listed separately. The documented FBA profit calculation subtracts totalCost and the off-peak monthly storage fee from the selling price. The returned peak-season storage estimate is a separate field, not the storage amount used in that profit formula.

MFN has no Amazon fulfillment or storage fee in this summary: its documented total is the net referral fee plus any fixed closing fee, and the profit field subtracts that total from the MFN selling price. The exact fee items can vary with what Amazon returns. The response also includes raw, the original fee breakdown, which may expose fee items that are not rolled into the summary.

There is a subtle naming distinction: amazonFeeTotal is documented as base referral fee plus fixed closing fee, while totalCost uses the net referral fee and, for FBA, also includes the fulfillment fee. Do not swap these fields when building your own comparison. Read the exact field definitions in the response schema.

Supply real prices and package measurements

Smart defaults are convenient for a first look: when omitted, the API uses the current product price and available product dimensions and weight. But the documentation warns that if no current price can be fetched, an omitted FBA or MFN price can fall back to 1. The calculated profit and margin then have no practical meaning. For a decision, pass a realistic price for each fulfillment scenario.

Dimensions and weight deserve a separate check. Amazon may use its internal measurements to calculate the fulfillment fee, but the API’s product.dimension and product.weight output fields remain zero unless you pass the corresponding package measurements. A zero in those returned fields therefore does not prove Amazon used a zero-size package; conversely, do not treat hidden/default measurements as verified inputs for your own model. If your packaging differs from the listing or fee classification matters, provide the actual package length, width, height and weight in the marketplace’s documented units and validate them against your own records.

Check the ASIN and marketplace too. This is a fee estimate tied to those inputs and the current Amazon fee response; it is not a universal rate card for every country or future date.

Add the costs outside Amazon’s fee estimate

The documented input and output contract is centered on Amazon’s fee calculation. It does not ask for your supplier price, freight to the fulfillment center, prep or labeling labor, advertising budget, return rate, financing cost, or your tax and duty treatment. Do not assume those expenses are included just because a response field is named profit. Add them in your own unit-economics sheet using the relevant quantities and time horizon.

Storage is especially easy to misread. The API returns peak and off-peak monthly storage estimates per unit, while the FBA profit formula uses the off-peak monthly value. If inventory is likely to sit through a different season or for longer than one month, model that duration separately instead of multiplying or replacing the API’s figure without checking your scenario.

Use the estimate as a sourcing filter

A practical workflow is to use the estimate to screen candidates, not to authorize a purchase order:

  1. Choose the marketplace and a plausible selling price for FBA and, if relevant, MFN.
  2. Supply measured package dimensions and weight when your packaging or fee tier could change the result.
  3. Compare the returned Amazon fee components and inspect raw when an extra fee matters.
  4. Subtract supplier, shipping, prep, ads, expected returns and other seller-specific costs in your own model.
  5. Stress-test the result with lower selling prices, longer storage, or other realistic operating assumptions before committing to inventory.

The Revenue Calculator endpoint is documented at five credits per request, and the API reference notes a relatively low source-IP threshold: concurrent requests at QPS 3 or higher can trigger rate limits. If you are planning repeated checks, use the current pricing page and the live endpoint documentation to estimate usage and design a modest request rate. Cost and availability terms can change.

Questions sellers should settle before committing

Is the API’s “profit” my true net profit? No—not by itself. It is the result of the documented Amazon-fee calculation for the supplied or default price. It does not include your full landed cost and seller operating expenses.

Why did my returned product dimensions show zero? The reference says Amazon’s anonymous fee service does not return those measurements in this response. Unless you pass package dimensions and weight, the output fields can be zero even though Amazon used internal measurements to calculate fees.

Can I compare FBA and MFN? Yes, for the supported US and JP country codes, using the same product and realistic scenario-specific prices. Add MFN shipping when it matters, and make sure you compare equivalent seller costs outside the API.

What should I verify before a real sourcing decision? Confirm the marketplace, selling price, package measurements, storage duration, Amazon fee fields, supplier cost and delivery-to-fulfillment costs. The estimate is a useful early filter; your own complete margin model is the decision tool. For the API’s broader product-data capabilities, see the Amazon Scraper API and the operation-specific Revenue Calculator API reference.
